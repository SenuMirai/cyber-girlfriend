### IExpress 三个坑（血泪，务必记住）
1. **`.sed` 的 `[SourceFiles0]` 段每行必须写成 `%FILE0%=`，末尾等号不能省** ——
   少了它 IExpress 只返回退出码 1，不弹窗、不报错、**什么文件都不产出**，极难排查。
2. **`.sed` 里不能出现中文**（IExpress 只认 ANSI 且对中文路径极脆弱）→
   先输出到临时 ASCII 路径（`os.tmpdir()`），打包成功后再 copy 到中文交付目录；`FriendlyName` 也用英文。
3. **安装包的临时解压目录事后会被系统清掉** → 说明书必须在 install.cmd 里显式 copy 到目标目录，
   否则用户装完就找不到（第一版安装包就踩了这个）。

### 其他环境事实
- `%TEMP%` 变量即 `os.tmpdir()`，可作 IExpress 的中转站。
- Node 22（managed 版）**支持** `new TextDecoder("gbk")`（full-icu），可用于校验 GBK 模板；
  但 `Buffer.toString("gbk")` 不可靠，写 GBK 一律用 Python 或避免中文。
- 通过 Bash 工具启动的「分离子进程」会随该次工具调用结束被杀 →
  想验证常驻服务，必须用 `run_in_background: true` 让任务存活。
- `.workbuddy/tmp/` 下的临时目录名容易被误删，本轮统一改到 `os.tmpdir()/cg-installer-build` 并自清理。

## B 方案已实施完成（同日）· 用户指令「让他们用自己的key，其他的按你说的做」

### 最终形态：一个程序两种模式
`CG_PUBLIC=1` → 公网模式；不设 → 本机自用模式（原有局域网/HTTPS/二维码全部保留，互不干扰）。

### 服务端改造（server.mjs）
- **每请求上下文 AsyncLocalStorage**：`ctxStore.run(c, ...)` 包住整个 `handleInner`。
  `ctx()` 取当前请求的 `clientId/dir/apiKey/voiceKey/secure/host/proto`，
  `configPath()/libraryPath()/uploadDir()` 全部改成从 ctx 推导 —— 这是多用户不串数据的地基。
- **身份**：cookie `cg_cid`（`^[A-Za-z0-9_-]{8,64}$` 校验，`Max-Age=CG_CLIENT_TTL_DAYS*86400`，SameSite=Lax）。
  `DATA_ROOT/clients/<cid>/` 一人一份。
- **BYOK**：`X-Vivix-Key` / `X-Voice-Key` 请求头。优先级 请求头 > 环境变量 `VIVIX_API_KEY` >
  （公网模式到此为止，返回空）> 本机 config.json。
  公网模式 `loadConfig()` 强制清空 `api_key` 与 `voice.tts_api_key`，`persistConfig()` 直接 `delete out.api_key`。
- **会话按客户端隔离**：原 `let sessionId` 全局单例 → `const clientStates = new Map()`，
  key 是 `ctx().clientId || "__local__"`。**不这么改的话公网下所有人抢同一个会话**。
- **上传公网化**：`publicUploadDir()` 故意**不按用户隔离** —— 因为 Vivix 服务器来抓图时不带 cookie，
  隔离了就抓不到。文件名用 `randomUUID()`（不按用户隔离就没法靠用户名区分，用随机名防猜）。
- **公网地址推导** `publicBaseUrl()`：`PUBLIC_BASE_URL` 环境变量 > 公网模式按 `x-forwarded-proto/host` 推断 >
  本机 config.json。图片直链 = `${base}/assets/uploads/<name>`。
- 新增 `/health`（`ok/mode/version/uptime_seconds/clients`，平台健康检查用）；
  公网模式 `/shutdown` → 403；新增 `sweepClients()` 按 TTL 清过期目录（6h 一次，`.unref()`）。
- `main()` 公网分支跳过 `ensureCert`/HTTPS/局域网打印，只听 `0.0.0.0:$PORT`。

### 前端改造（src/main.js）
- `apiFetch(path, options)` 统一包装（15 处 `fetch(` 全换），自动加 `X-Vivix-Key`/`X-Voice-Key` + `credentials:"same-origin"`。
- Key 存 localStorage：`cg_vivix_key` / `cg_voice_key`。**只在使用者浏览器里，不上传服务器**。
- `applyModeUI()`：公网模式隐藏 `#net-local-opts`、标题改「分享给朋友」、
  Key 标签改「你自己的 Vivix API Key」、占位符改「只存在你的浏览器里，不会上传」。
- 首次访问若无 Key 自动弹出设置面板。
- `public/index.html` 配合加了 `#api-key-label` / `#net-title` / `#net-local-opts` 三个钩子。

### 部署文件（全部新增）
`Dockerfile`（两段构建、`USER node`、HEALTHCHECK 打 /health）、`.dockerignore`、
`render.yaml`（`plan:free` + `healthCheckPath:/health`）、`.env.example`、**`DEPLOY.md`**（三条路的点击级教程 + FAQ）。

### 本机环境坑（本轮新增）
- **bash 里 `&` 启动的分离进程会在该轮工具调用结束时被回收** → 要验证常驻服务必须用

### 以后要用的 Render API 调用（可直接复用）
```bash
RK=<api key>
# 1) 取 workspace
curl -s -H "Authorization: Bearer $RK" https://api.render.com/v1/owners
# 2) 建服务（body 见下）
curl -s -X POST https://api.render.com/v1/services \
  -H "Authorization: Bearer $RK" -H "Content-Type: application/json" -d @body.json
# 3) 设环境变量（整体覆盖式 PUT，数组 [{key,value}]）
curl -s -X PUT https://api.render.com/v1/services/$SID/env-vars \
  -H "Authorization: Bearer $RK" -H "Content-Type: application/json" -d @env.json
# 4) 看部署 / 触发部署
curl -s -H "Authorization: Bearer $RK" "https://api.render.com/v1/services/$SID/deploys?limit=5"
```

```json
{"type":"web_service","name":"cyber-girlfriend","ownerId":"tea-...",
```
