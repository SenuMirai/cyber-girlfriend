### 一、隐私：首屏闪出用户本人的照片（用户报障）
**根因**：`assets/character.jpg`（106865 B，md5 `0f5a42af46cb9f2cc59fe01d47b3df53`）就是用户本人的照片，
被当成"首屏占位图"硬编码在 4 处 —— 浏览器一解析 HTML 就画出来，等 `/config` 回来才切成大肥鱼，
所以看起来是"打开一瞬间闪过我的照片"。

**修法（服务端按访问者注入，从根上消除闪烁）**：
- `public/index.html` 的 `#poster` → `src="__POSTER_HTML__"`；`public/style.css` 的
  `--poster-url` → `url("__POSTER_CSS__")`。
- `server.mjs` 新增 `DEFAULT_POSTER` / `posterUrlFor(cfg)` / `renderTemplated(rel)`；
  `STATIC_FILES` 值加第三个元素 `"tpl"` 表示"先过模板再发"，
  `/`、`/index.html`、`/style.css` 都走它；`send()` 本来就带 `Cache-Control: no-store`，
  因人而异的响应不会进共享缓存。
- ⚠️ 坑：`__POSTER_CSS__` 在 CSS 里已经包在 `url("...")` 里，只能替成**裸地址**；
  一开始替成 `url("...")` 结果变成 `url("url("...")")`。
- 前端 `previewUrlFor()` 的兜底改成 `defaultPosterUrl()`（沿用服务端已注入的 `#poster.src`，
  兜底 `/assets/1791525005312.jpg`），不再写死文件名。
- 删掉 `assets/character.jpg`，`Dockerfile` 与 `tools/build-exe.mjs` 的 EMBED 同步；
  内置默认图 `assets/1791525005312.jpg` 兼作占位图（新 exe 里验过：含大肥鱼 base64、不含照片）。

### 三、语音说到中途断掉（用户报障）
**根因**：Vivix 的 `response.create` 默认 `scheduling_policy: "interrupt"`。
她还在说的时候又来一条请求，就会把她那句拦腰切断 —— 答案越长越容易撞上，
正好对上用户说的「长句子容易遇到」。
**修法（客户端排队）**：
- 新增 `state.speaking` / `responsePending` / `answerQueue` / `userCancelled` / `speakingWatchdog`。
- `requestResponse()`：忙就 `answerQueue += 1`，否则发 `response.create`。
- `beginSpeaking()` 在 `response.created` / `response.render.started`；
  `endSpeaking()` 在 `response.done`，随即 `drainAnswerQueue()` 依次补发。
- 看门狗：只要有事件进来就重新计时，**真的 120 秒没动静**才兜底放行，避免队列卡死。
- 「打断」按钮仍即时 `response.cancel`，并置 `userCancelled`，不把它当故障报出来。
- **`response.render.stopped.status` 与 `response.done.status` 以前被静默吞掉**，
  现在非正常结束会在聊天里如实写一行（`reportResponseOutcome`）。
- 输入框回车补 `keyCode === 229` 判断，中文输入法选字不再误发消息。

**无法真机复现**：用户 Vivix Key 返回 `insufficient workspace balance`（code 10005），
所以排队逻辑只做了桩件集成测试（12/12 通过），没跑真实会话。
